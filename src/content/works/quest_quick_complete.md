## 기획 배경 및 목적

하나의 계정으로 여러 캐릭터를 육성할 경우, 이미 다른 캐릭터로 진행한 경험이 있는 메인 퀘스트를 다시 플레이해야 하는 부담이 있었습니다.

그래서 이 부담을 완화하기 위해, 계정 내에서 메인 퀘스트 진행도가 가장 높은 캐릭터가 완료한 메인 퀘스트는 계정 내 다른 캐릭터가 재화를 소모하여 일괄 완료하는 기능을 기획했습니다.

이를 통해 부 캐릭터 육성의 편의성을 높이고, 반복적인 퀘스트 진행에 대한 부담을 줄여 새로운 캐릭터의 육성을 유도하고자 했습니다.

#### 기획 의도 및 방향성

- 이미 다른 캐릭터로 완료한 메인 퀘스트의 반복 플레이 부담 완화
- 퀘스트 챕터별로 일괄 완료 범위를 구분
- 재화를 소모하도록 하여 편의 기능 이용에 대한 비용 구조 설정
- 퀘스트 완료와 연결된 보상·진행도·튜토리얼 등의 연계 콘텐츠까지 함께 처리하여 기존 플레이와의 정합성 유지

## 핵심 시스템 구조

#### 이용 조건 및 진행 방식
- 계정 내 메인 퀘스트 진행도가 가장 높은 캐릭터가 모든 퀘스트를 완료한 챕터에 한해 일괄 완료 가능
- 챕터 단위로 일괄 완료 적용
- 일부 퀘스트를 진행 중인 상태에서도 일괄 완료 이용 가능

챕터 단위로 일괄 완료 범위를 구분하고, 챕터 내 일부 퀘스트를 진행한 상태에서도 기능을 이용할 수 있는 유연한 구조로 설계했습니다.

#### 재화 및 보상 처리
- 챕터별로 일괄 완료에 필요한 재화 종류와 수량 설정
- 해당 챕터의 기존 진행도와 관계없이 동일한 비용 적용
- 일괄 완료되는 퀘스트의 보상을 즉시 일괄 지급
    - 이미 완료한 퀘스트의 보상은 중복 지급하지 않음
- 완료 처리된 퀘스트 수만큼 챕터별 이야기 진행도 반영

일부 퀘스트를 직접 완료한 상태에서 기능을 이용하는 경우를 고려하여, 기존에 획득한 보상은 중복 지급되지 않도록 처리하고 새롭게 완료되는 퀘스트의 보상만 일괄 지급되도록 설계했습니다.

#### 연계 콘텐츠 및 예외 처리
- 메인 퀘스트 완료를 조건으로 하는 던전 및 콘텐츠 해금 처리
- 즉시 완료한 퀘스트와 연결된 퀘스트 던전 클리어 처리
- 메인 퀘스트 수락·완료를 시작 조건으로 하는 튜토리얼 스킵 처리

메인 퀘스트는 던전 입장, 콘텐츠 해금, 튜토리얼 등 다양한 콘텐츠의 이용 조건으로 활용되고 있어, 일괄 완료 시 관련 콘텐츠에 미치는 영향을 함께 검토했습니다.

## 데이터 및 UI

### 데이터 설계
- 일괄 완료 대상 챕터와 이용 비용, 연계 던전 정보를 관리할 수 있도록 신규 데이터 구조 설계

| 데이터 컬럼명 | 타입 | 설명 |
| :--- | :--- | :--- |
| quest_chapter | int | 일괄 완료 대상 챕터 설정 |
| price | key_value | 일괄 완료에 필요한 재화 및 비용 설정 |
| clear_map | array[int] | 일괄 완료 시 클리어 처리할 연계 던전 설정 |

※ 위의 표는 데이터 구조 설계 설명을 위해 재구성한 예시입니다.
